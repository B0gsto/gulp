# Sprint 0 technical spike, part A: results (Mac, Studio play tests)

Measured on 13–14 October 2026 on the 16 GB Mac. Roblox Studio ran one-process play tests (server and client in
one process), driven through the Studio MCP by `spike/tools/drive.py`. Every hold took the machine `studio` lock,
then one `heavy` slot, then the worktree's `.locks/studio` (`spike/tools/held.sh`).

- **Place:** `rojo build spike/spike.project.json -o spike/build/spike.rbxl`, opened with
  `tools/studio-open.py --tag gulp-spike`.
- **Runs:**
  - 10 + 1 short play starts (`drive.py s1`).
  - Three full measurement runs (`drive.py main`). Run 1 was on a build still using LegacyChatService (see
    surprise 1); runs 2 and 3 are on the final build.
  - One two-client attempt (`mp_probe.py`).
- **Raw numbers:** `spike/results/raw/*.json`.
- **Phones:** none of this was run on a phone. Every phone criterion below is "not run (needs device row 1)".

## Surprises (behaviour that differs from what chapter 09 assumes or leaves open)

1. **A Rojo-built place defaults to `LegacyChatService`.** `TextChatService.ChatVersion` cannot be written even by plugin/MCP code ("lacking capability RobloxScript"). It must be set in the project file (`"TextChatService": {"$properties": {"ChatVersion": "TextChatService"}}`). Under legacy chat, `DisplayBubble` fails silently, and the legacy `ChatScript`, `BubbleChat` and the `Chat` ScreenGui are inserted.
2. **Streaming properties are not even readable** from scripts or plugin code (`StreamingMinRadius`, `StreamingTargetRadius`, `StreamingIntegrityMode` and `ModelStreamingBehavior` are "not a valid member"). Only `StreamingEnabled` reads. The Rojo project file sets all of them correctly. 09 §6.6 says "set by hand in Studio", but the project file is enough.
3. **Persistent models are not there when StarterPlayerScripts start**, even with `game:IsLoaded()` true, and `GameplayPaused` is already true at that moment. Client code must wait for `workspace.PersistentLoaded` before it relies on the shell. In practice the shell was always complete by `CharacterAdded`.
4. **Join latency:** the client's `CharacterAdded` came 0.34–0.91 s after ClientReady even in local Studio (the server side takes under 3 ms). That is close to the 6.3 budget of "controllable within 1.0 s of ClientReady". It is worth measuring on a real server with the real map.
5. **PauseOutsideLoadedArea with a non-Humanoid character** freezes the owner's root in place without anchoring it (and `AssemblyLinearVelocity` still reads about 21 studs/s). It also fired once 0.7 s after joining, for 56–69 ms, in runs 2 and 3.
6. **Studio throttles a background window to 15 fps.** Run 3 measured exactly 66.7 ms frames at every scale. Mac frame-time numbers are only valid with Studio in front, and the 60 fps values are capped by vsync. Neither stands in for a phone.
7. **`luau-lsp analyze --platform roblox` does not load Roblox globals by itself** (U16 settled). It needs `--definitions @roblox=<globalTypes.d.luau>`; without it every Roblox global is "unknown" (the shared modules pass anyway because they use none).
8. **Rojo 7.7.1 rejects the implicit `CFrame` property form** (`{"position", "orientation"}`) with only "Failed to deserialize JSON". The explicit `{"CFrame": {...}}` wrapper works.
9. **The MCP lists a freshly opened Rojo-built place as `"Game"`** until it is reopened, so `drive.py` identifies the window by a read-only fingerprint. Test-session instances are listed with `name: null`.
10. **`player.Character = model` with no Humanoid** produced no core-script errors (U1 settled for Mac Studio). The default `RbxCharacterSounds` and `PlayerScriptsLoader` are still inserted and stay silent.
11. **A hostile client can move its local copy** of an anchored, server-owned root (up to 62 studs in the test). Server state is unaffected, and the next server write snaps the copy back.
